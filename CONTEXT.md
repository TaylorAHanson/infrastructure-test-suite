# CONTEXT — Databricks Validation Platform

Ubiquitous language for the platform. Use these terms **exactly** in code, issues, tests, and UI — don't drift to synonyms. New concepts get added here as they're decided (see `docs/adr/`).

> Status: seeded while resolving the test & result model ([#2](https://github.com/databricks-field-eng/infrastructure-test-suite/issues/2), ADR-0001). Target and safety details are finalised in [#3](https://github.com/databricks-field-eng/infrastructure-test-suite/issues/3) / [#6](https://github.com/databricks-field-eng/infrastructure-test-suite/issues/6).

In one line: a **Test** is a Python script, and a **Check** is the result of one `with check("…"):` block in it. The structured Tests that came before scripts were removed in v1.1.0; their vocabulary is under [Retired terms](#retired-terms).

## Core vocabulary

- **Validation Platform** — this app. A Databricks-native platform that regression- and connectivity-validates infra changes across many environments.
- **Test** — a **user-facing, target-agnostic** capability assertion, written as a **Python script** (its **Test script**). Its Checks are the script's `with check("…"):` blocks, **including counterfactuals**. Passes iff every gating Check meets its expected outcome. *Defined once, applied to any target.* There is no other kind of Test. Each save is a new **Test version** of the whole script; rolling back saves an earlier version's script as the next version. A Check keeps its id while its name is unchanged, so run history stays continuous across edits.
- **Check** — the **atomic** unit of validation: the result of **one `with check("…"):` block** (or `with expect_deny("…"):` block) of a Test script against one bound Target, producing a **staged result** + **evidence** (whatever the block `record()`s). It passes when the block finishes without a failed `assert` or API error; a counterfactual passes when the refusal it asked for happens. Named by its literal string, which is its identity. Read-only outside the script: to change a Check, edit the script.
- **Advisory** — a Check marked `advisory=True` in its script: its result is recorded and rolled into the failure-taxonomy summary as *signal* (surfaced in Runs and the "what's interesting" view, #10) but is **never a fail-closed gate input**. Flaky findings are advisory too, so a flaky verdict can never block a pipeline. (ADR-0008.)
- **Test script** — the source of a Test: a **Python script**. Each `with check("…"):` block declares one Check (`with expect_deny("…"):` declares a counterfactual), named by its literal string, which is what keeps a Check's id and run history across edits. The script calls Databricks only through the pre-bound `w` (SDK), `w.api` (raw REST), `sql()` and `http()`; it runs in a **credential-less subprocess** and every call is **brokered** by the platform through the safety gate (blocklist → tier vs. safety class → override), with mutating calls skipped at `quick` depth. One script run per Target produces one CheckRun per declared check.
- **Test editor** — the page where a Test script is written (`/tests/:id/edit`, `/tests/new`): a code editor and the **editor assistant** side by side in one resizable box, live static analysis (unknown SDK methods, blocklisted calls), and **dry runs** — one execution of the buffer against a chosen Target that records nothing. The editor assistant is the **Assistant**'s authoring capability given editor tools (SDK search/describe, read-only `sdk_call` and SQL, allowlisted docs, edit, validate, dry-run). It shows its **work log** live — each lookup, edit and dry run as it happens, with timings — and can be stopped mid-turn. It makes **targeted edits**, never saves, and every edit is a diff the human reviews change by change (**Keep** / **Undo**, or **Keep all** / **Undo all**). Its model and limits are the **Assistant settings**.
- **Assistant settings** — one global, audited Lakebase record: the Assistant's **model** (any chat endpoint in the workspace, foundation `system.ai` models first; empty = the deployment default) and **reasoning** level, and for the editor assistant its **per-turn limits** (tool calls, time, output tokens, temperature) and whether it may **read live data** or **dry-run** on the selected Target. Edited under **Settings → Assistant** by any authenticated human (ADR-0010) with no friction ceremony — what it allows still runs as the Target's identity through its safety gate.
- **Counterfactual** — a Check whose **expected outcome is a denial** (pass = it was correctly refused at the expected stage): a `with expect_deny("…"):` block. E.g. "a non-compliant cluster is denied by policy P." It counts only the refusal asked for — a permission denial by default, a network block with `at="CONNECT"` — never an outage or a broken identity.
- **Suite** — a selection of **Tests + targets** chosen for a run; the scheduling/selection grouping. In the GUI a Suite has no page of its own — it is a **filter chip** on the Tests view, created and edited **by hand** (name, ordered Tests); the Assistant does not compose Suites. (No depth of its own — depth is a Run dial, ADR-0007.) A Suite the CI trigger runs (the bundled **CI Gate**) holds only read-only Tests with no advisory Checks.
- **Target** — one Databricks **workspace** under test (~100 of them). Target-agnostic Tests are **bound to a Target at run time**. **Registered manually / opt-in** (a never-registered workspace can never be touched). Addressed on the wire by **workspace name** (primary), or optionally **host** or **workspace_id** — one required (ADR-0005). Carries a **safety class**, an **identity handle** (its OAuth M2M service principal, referenced as a Databricks secret-scope `scope/key` — ADR-0003), and optional **tags**. Finer scope (catalog/warehouse/policy) lives in **Check params**, not in separate targets. *(The "what changed → which target(s)" resolution is the **caller's** job, not the app's — ADR-0005.)*
- **Run** — one execution of a Suite (or Test) against selected Targets.
- **Target lock (lease)** — the mutual exclusion that serializes Runs on a mutating Target. **Gated by safety class**: `read-only` Targets **never lock** (no mutation to interfere — concurrent runs allowed), while `prod-for-us` and `sandbox` Targets allow **at most one active Run at a time** — otherwise two mutating runs would trample state and yield untrustworthy Verdicts. The lock is a **Lakebase lease** (authoritative store, ADR-0001) with a **TTL renewed by heartbeat**; a lapsed lease (crash, or a **server-side max run duration** — distinct from the caller-owned timeout) is reclaimable by the next queued Run, so a dead holder can't deadlock a Target. No external lock service. (ADR-0011.)
- **`queued`** — a **non-terminal** Run phase: a Run waiting on a locked Target (per-target **FIFO**). It is **not a Verdict** — the CI contract (ADR-0005) sees only "not terminal yet" and keeps polling, so the fail-closed mapping is unchanged and the lock is invisible to callers. Queue depth is unbounded FIFO for now (a max-queue-depth / per-run deadline for bursty CI is fog). (ADR-0011.)
- **Canonical stage spine** — the shared, ordered vocabulary every Check's result maps onto: `RESOLVE → CONNECT → TLS → AUTHENTICATE → AUTHORIZE → OPERATE → VERIFY`. A Check **skips** stages it never reached; nothing **invents** private stages. A failed `assert` fails at `VERIFY`.
- **Failure classification** — an **extensible taxonomy** over the stages: the category of a failure.
- **Connectable / Functional** — a **DERIVED VIEW** over the stage reached, **not** a stored primitive. Failure ≤ `AUTHORIZE` = connectivity; failure at `OPERATE`/`VERIFY` = functional. A `BLOCKED_BY_SAFETY` or `SKIPPED` Check never reached the workspace, so it counts toward neither; a `quick` Run reports functional as *n/a*.
- **Depth** — a coarse dial on a **Run** for how far up the stage spine it executes: **`quick`** (connectivity/read-only end — fast) vs **`full`** (through `OPERATE`/`VERIFY`). **Defaults to `quick`, never `full`** — a `full` run is always an explicit opt-in (CI relies on this; nightly opts into `full`). One dial, one run, one verdict. Levels stay adaptable — only `quick`/`full` ship. (ADR-0007.) At `quick` a script makes **read calls only**: a mutating call is skipped and its Check is recorded **`SKIPPED`**, never judged against evidence it didn't fetch.
- **Run concurrency** — a configurable bounded max-parallelism setting on in-app run execution (Runs execute **in-app, concurrently** — no Databricks Job fan-out). The single lever for fan-out across ~100 targets; cost accounting is deliberately out of scope. (ADR-0007.)
- **Risk tier** — the danger a call carries, **derived from the call** (its verb, and for SQL what the statement does) and the blocklist (ADR-0017): **R0** read · **R1** safe mutation (create dashboard) · **R2** destructive (delete dashboard) · **R3** catastrophic (delete workspace). A Check's tier is the highest of its calls'. Gated against a Target's safety class; **R3 is globally forbidden**. (Enforcement: the **safety gate**, ADR-0004.)
- **Safety class** — a Target's **explicit, authoritative** field capping the **max risk tier** it will run (`read-only` / `prod-for-us` / `sandbox`). **Never derived from the workspace name** (the label lies). Changing it is a **friction-ceremony-guarded**, audited action — any authenticated **human** app user may change it, but only through a GUI confirmation gauntlet, not a permission gate (the `prod-for-us`→`sandbox` downgrade is the dangerous edit; ADR-0010). Rare audited per-target exceptions allowed; default none. (Enforcement matrix: #6.)
- **Tag** — an optional `key=value` label on a Target, used only as a **filter chip** to navigate the target list and for one-click multi-select — **not** a query language. `environment` (dev/stage/prod) is just a tag; safety class is the real control.
- **Target selection** — always **explicit, no implicit default**: GUI = a picker with "All" at the top + individual targets; API = named target(s) or explicit `"all"`; CI = **explicit target(s) the caller passes** (the caller owns "what changed → which target"; tool-agnostic — Terraform/CloudFormation/human, none privileged — ADR-0005). Even "All" is safe — the per-target safety gate fires per target.
- **Identity handle** — a Target's reference to its **OAuth M2M service principal**, stored as a Databricks secret-scope `scope/key`. The app mints short-lived tokens on demand (never persisted); the SP secret rotates in the scope out-of-band. Each SP is least-privilege — never workspace-admin. A Run's effective identity is `(target, assumed-role?)` — the SP by default, or a **Run-as-role** it assumes (ADR-0003, amended by ADR-0018). (ADR-0003.)
- **Run-as-role** — an optional per-Test attribute: a Test runs as the target's own SP (**default**) *or* **assumes exactly one registered role-profile**, letting the platform ask *"is the **analyst profile** denied cluster-create under policy P?"* — the **denied** side of a counterfactual (ADR-0001). Mechanism (Databricks RBAC, Preview): the per-target SP adds `assume_group=<group-id>` to its workspace-level `client_credentials` token request — non-interactive/CI-safe, no new creds, the role's grants **replace** the SP's for the token's 1 h life, audited as `run_by`(SP)+`run_as`(role). **Role/group granularity only** — no named-user. The set of assumable **role-profiles** is registered **with the Target** and **capped by its safety class** (a `read-only` Target may attach only read-only roles), so an assumed identity can never out-run the Target's class — the load-bearing control given that identity is the *primary* blast-radius bound (ADR-0017). (ADR-0018, amending ADR-0003/0004.)
- **Safety gate** — the enforcement that stops any call a script makes whose **risk tier** exceeds the target's **safety class** cap. Three independent layers: (1) the run **engine**, which brokers every script call, (2) the shared outbound **client wrapper** at call time, (3) the least-privilege **SP** in Databricks IAM. R3 is a wall through all three.
- **Safety override** — the human-only, GUI-only, per-run, typed-confirmation, audited action that authorizes an **R2** op on a `prod-for-us` target. Any authenticated **human** app user may exercise it (no role gate); its typed confirmation is a **friction ceremony**, not a permission (ADR-0010). **Never available to CI/automation.**
- **Access model** — the platform ships **no app-local authorization**: authentication is the **host Databricks App identity** (every user is a workspace user; no app-local accounts), and every authenticated **human** app user has **full capability** — register/edit targets, set/downgrade safety class, author/edit Tests, trigger runs, exercise the override. No roles, no admin group, no per-object ACLs. Controls are **structural** (R3 globally forbidden, ADR-0004), **ceremonial** (friction ceremony on the dangerous edits), and **forensic** (audit is the standing control). Governs **humans only** — machine identities stay least-privilege (CI trigger scoped to trigger+read, ADR-0005; per-target SPs, ADR-0003). Preventive control is layered in the host workspace (who gets access to the App at all), not reinvented in the app. (ADR-0010.)
- **Friction ceremony** — the GUI-only confirmation gauntlet that guards the dangerous, safety-gate-defeating actions (**safety-class change** and **safety override**) in lieu of a permission gate: escalating warnings that state concretely what is about to be allowed and why it is dangerous, ending in an **AWS-style typed confirmation** (e.g. type "i understand"). Friction as *gesture*, not *permission* — deliberately high-friction so the action can't be a slip, then fully audited. (ADR-0010.)
- **Audit log** — the **standing forensic control** that makes the no-roles access model (ADR-0010) defensible: a single **append-only** Lakebase table (no in-app edit/delete) recording **config-plane mutations only** — target register/edit/deregister, **safety-class change** (before→after, downgrades flagged), **safety override** (with the typed-ceremony reason), **branding edit**, and **Test create/edit** (as a **version pointer**, not a duplicated diff). **Runs are not audited** — the retained-history model (#16) covers them. Each record captures actor (**host Databricks App identity**), timestamp, event type, entity ref, before→after (or version pointer), and the ceremony reason for the two friction-gated edits. **Unbounded retention** (config-mutation volume is tiny; revisit only if it bites). Surfaced as a **read-only GUI view** filterable by target · actor · event type (per-target and global entry points), **exportable**, and directly queryable in Lakebase — no bespoke audit API. (ADR-0014.)
- **`BLOCKED_BY_SAFETY`** — the result status for a Check whose call the safety gate stopped: not a pass, not a functional failure, surfaced loudly.
- **Open-SDK authoring** — a Test script may make **any Databricks SDK/API call**, bounded by a **blocklist**, not a curated allowlist (ADR-0017). The **Assistant** grounds on the **live SDK/OpenAPI surface**, so a new kind of check needs no pre-declared operation. Primary shapes are the **nightly run of "all"** (the saved-Test corpus) + the **on-demand Run API** for a Test/Suite; a run still returns a **verdict** (ADR-0005) — CI-gating is a caller concern, not a design driver.
- **Identity-bounded safety** — the blast-radius control order under open-SDK (ADR-0017, amending ADR-0004): **(a)** the **least-privilege per-target SP / assumed role** (ADR-0003; assumed role per ADR-0018) is the *primary* hard bound — a destructive call on a `read-only` Target just fails with a permission error, safe by construction (and a Test's optional **Run-as-role** can only assume roles whose grants stay within the Target's safety class, so assumption can't widen this bound); **(b)** the **blocklist** is the global **R3-never floor**; **(c)** a **coarse verb/category-derived risk tier** (`GET`→low, mutating verbs→higher) checked against the Target's **safety class** is a *secondary* cap. A **one-confirm operation-specific tier** is captured (suggest-then-confirm) **only** for operations against **mutating** (`sandbox`/`prod-for-us`) Targets, where a coarse verb guess could under-classify a catastrophic call; `read-only` Targets need none.
- **Assistant** — the **single, app-wide AI agent**. There is exactly **one** assistant (one Model-Serving endpoint, chosen in **Assistant settings**; one grounding harness); its two capability areas — **authoring** and **triage/RCA** — are differentiated by the **tools** it's given, not by being separate agents (ADR-0012). Delivered via the **Assistant shelf**; **page-aware** (see **Assistant page context**). Guardrails ride on the **tools, not the agent**: write-path tools keep the authoring contract below (static analysis, R3 refusal, never saving), read-path/RCA tools are read-only and **advisory** (ADR-0008). A turn runs as a **LangGraph tool-calling loop** — the model decides per turn which tool(s) to call from a **closed inventory** of read/grounding tools (the editor assistant adds edit, validate and dry-run, which touch only the editor's buffer) — and that inventory is **closed by omission**: no schema exists for a Target write, `/admin/*`, Branding, or Webhook action, so those are unreachable by design (ADR-0019/0020). Its **display name is a Branding setting** (default `Assistant`), not a fixed term — the ubiquitous term is always *the Assistant*.
- **Assistant shelf** — the app-wide UI for the **Assistant**: a consistent, quick **slide-out shelf** available on **every page** (not embedded in any single view). The single way a user reaches the Assistant anywhere in the app. It answers questions and suggests causes; a request to write a test is handed to the **Test editor**. An empty conversation offers a few **starter prompts**, each one such request. (ADR-0012.)
- **Branding settings** — a single **global Lakebase record** carrying the deployment's **presentation-layer** white-label fields: **app name**, **logo**, **favicon**, **Assistant display name** (default `Assistant`), a **theme** (an accent colour + a **closed set of named design tokens**, applied as **CSS custom properties**, light/dark-aware — never free-form CSS/JS), and **footer/attribution text**. **Fixed, closed schema** — **presentation only, never behaviour**; a new field is a code migration, never a runtime "add setting." Logo/favicon are **Lakebase blobs** (≤ 1 MB, PNG/SVG). **Instant-apply**: the shell reads it on load and the **existing poll** refreshes it — no redeploy, no new push infra. **Defaults ship seeded in the repo** (`Validation Platform`, `Assistant`, text wordmark when no logo, the default token palette) so an un-branded install looks finished. Editable by **any authenticated human** (ADR-0010) with **no friction ceremony** (presentation can't defeat a safety gate) but **audited** like other config mutations. (ADR-0013.)
- **Assistant page context** — the declared context each surface hands the **Assistant** so it can offer suggestions grounded in what's on screen (the current finding, the Test being edited, the target list, …). A contract — *what* each page declares — not a plumbing detail. (ADR-0012.)
- **Authoring** *(Assistant capability, formerly "AI Authoring Assistant")* — the Assistant's write-path: turns a **plain-English** intent ("start a cluster under policy P and confirm it's allowed") into a **Test script**, in the **Test editor**. Grounds by **tool-calling**: SDK search and signatures, allowlisted docs, and (if **Assistant settings** allow) read-only calls and **dry runs** against the selected Target. Its output is **never trusted raw**: every edit passes the editor's static analysis, it refuses **R3** calls, and it **never saves** — each edit is a diff the human keeps or undoes. Practises **guided authoring** — proactively suggests the steps a novice wouldn't know to take (counterfactuals, `record()`ed evidence, suite placement), always **suggest-then-human-confirms**. Creates *and* edits Tests. Non-determinism is tolerable because authoring is human-in-the-loop. (#8, ADR-0006; unified under the Assistant by ADR-0012.)
- **Test Studio** — the lifecycle where the Assistant and humans build Tests. In the GUI it is **not its own page**: it is the detail pane of the single **Tests** view (select a Test to review its Checks, run it, accept it or roll it back). Lifecycle: **`Draft`** (unsaved) → **explicit human accept** → **`Active`**; editing an Active Test **creates a new version** (Lakebase-authoritative rollback, ADR-0001), old versions retained. Surfaces each Test's **last runs** and, per Check, the calls it makes and the role it runs as. Creation is **New test**, which opens the **Test editor** on a starter script; asking the Assistant shelf to write a test hands the sentence to the editor assistant. (Supersedes ADR-0021's shelf-only creation path.)
- **Run-completion webhook** — the platform's only **push** notification: a **single generic outbound HTTP POST** to a configured URL — **not** a baked-in Slack/email integration (adopters point it at their own receiver). Exists for the **overnight-drift gap** (a nightly regression no one is polling for); CI polls and the SSC gets pass/fail (ADR-0005), so neither needs it. Config is a **Lakebase record** (URL[s]), editable by **any authenticated human** (ADR-0010) and **audited** (ADR-0014). **Fires when a completed run produces ≥ 1 finding** — exactly when the "What's Interesting" view (#10) would surface something — **silent on all-green runs** (a toggle can widen to every completion); reuses #10 findings + #16 last-good, no new regression logic. **Payload** = verdict + finding summary (`bucket @ stage`) + commit/event ref + a **deep link** into the view. **Best-effort** (bounded retry, failures logged; no durable delivery queue) — it is a *nudge*, the view + Lakebase stay the source of truth. (ADR-0016.)
- **Run API** — the single HTTP contract all three triggers (CI, GUI, nightly) share: `POST /runs` (start → returns a `run_id`) + `GET /runs/{run_id}` (poll → the verdict resource). CI is **just an authenticated caller** of it; there is no CI-only path. (ADR-0005.)
- **Verdict** — the terminal state of a Run, exposed on the run resource: overall `pass` / `fail` / `BLOCKED_BY_SAFETY` / `error` / `skipped` (every gating Check was skipped, so nothing was proven) (+ `running` until terminal), a per-Test roll-up, the **failure-taxonomy summary**, and the derived connectable/functional view. **Gating is fail-closed**: only `pass` passes the pipeline; every other terminal state (and a caller-side `timeout`) blocks it. (ADR-0005.) The roll-up separates **gating** from **advisory** Check results — advisory results are signal only and never affect the fail-closed gate (ADR-0008).
- **CI trigger** — the primary trigger: an authenticated caller (exemplified by a GitHub Action, not required to be one) that starts a Run via the Run API, **owns the poll/timeout loop**, and maps the verdict to a pass/fail exit. Authenticates as a **distinct identity from the target SPs** (OIDC-preferred), scoped to trigger + read only — never override, never safety-class change. (ADR-0005.)
- **Self-Service Center (SSC)** — a separate app (built in-house) that provisions workspaces/catalogs/service-principals; a **consumer** of this platform's results. It needs only whether the **deploy (apply + gate) succeeded or failed** — carried by the pipeline outcome — so there is **no dedicated verdict-fetch contract** for it (ADR-0005). Not a driver.
- **"What's Interesting" view** — the human-centric regression-triage GUI: *"what regressed since my change, and why"* across ~100 targets, ranked **signal-over-noise** (not 100 green rows). A **triage feed** of findings (not raw runs), organised into **two lanes shown on one screen** — the **Recent-deployments lane** and the **Overnight lane**. **Everything is a collapsed fold; nothing auto-expands** (scan first, dive on click); non-actionable counts collapse into one clickable **"Everything else"** footer. Failures shown as **`bucket @ stage`** (ADR-0001); connectable/functional is expand-only; flaky is advisory (ADR-0008). (#10, ADR-0009.)
- **Recent-deployments lane** — the commit-scoped half of the "What's Interesting" view: a **24h, newest-first list of CI-triggered Runs**, **bounded in height with infinite scroll** so deploy volume never pushes the rest of the page down. Answers *"CI emailed me — what's up?"* (ADR-0009.)
- **Overnight lane** — the time-window-scoped half of the view: fleet drift **not attributable to a specific deploy** (e.g. an infra/metastore change). Answers *"what happened while I was away?"* Placement between lanes is a **cause-attribution** judgment; absent attribution, default here. (ADR-0009.)
- **Commit provenance thread** — every finding's troubleshooting spine: **last-green → first-bad**, keyed to a commit `sha` or a non-deploy event ("metastore grant change · 21:14"). This is *diff-vs-last-good* expressed as **when it started**. Requires the run store to retain a per-`(target, check)` last-good verdict + recent history. (ADR-0009; the store that satisfies it is **Retained history**.)
- **Retained history** — the **minimum run history the core keeps** to serve **commit provenance** (#10) and **flaky detection** (#11) — a long-run BI/reporting surface is **out of scope** (point any dashboard at Lakebase). **Two Lakebase tables** (ADR-0001): **`runs`** (header: trigger · depth · target(s) · commit sha / non-deploy event ref · started/ended · overall verdict · phase) and **`check_results`** — the atomic record, one row per **run × target × check** (verdict · **`bucket @ stage`** · gating/advisory · evidence pointer · timestamp, with commit sha + target denormalized on). Indexed **`(target, check_id, timestamp desc)`**; last-good is **derived by query**, not a materialized table. **Retention = a configurable rolling window (default 90 days)** *plus* a preserved anchor — **the most-recent `green` per `(target, check_id)` is never pruned** so provenance stays honest for long-stable checks. Bounded (unlike the unbounded **Audit log**) because run/check volume is large; cost stays a non-goal, so the window is one generous knob. Distinct table + concern from the **Audit log** (config mutations, not runs). (ADR-0015.)
- **Triage / RCA** *(Assistant capability)* — the Assistant's read-path: tools to query **commit history + prior failures** and **attribute cause** — which ranks/sorts the "What's Interesting" lanes and answers *"why did this start failing?"*. Its tools (the **Commit provenance thread**, Run history, the failure archive of prior `bucket @ stage` occurrences, the Tests and their Checks) are **read-only**; its output is **suggest, never assert** — it proposes attributed cause + lane placement, deferring to the **Overnight** default when unsure (ADR-0009 §3), and is **advisory only, never a gate input** (ADR-0008). Not a separate agent from **Authoring** — same **Assistant**, different tools (ADR-0012). (#12, ADR-0012.)
- **Seed domain module** — the unit the bundled catalog (Spec #91) is built from: **one file per slice** under `app/services/seed/domains/` (today the three **health tiers** and the Connectivity Suite), declaring a `CONTRIBUTION` (or a `compose_contribution`, for a domain computed from every other's, e.g. the CI Gate). **Auto-discovered** — dropping in a new file registers it, no shared file (`__init__.py`/`build.py`/`registry.py`/`contribution.py`) needs an edit. A cross-module Check/Test key collision is a hard error (`SeedKeyCollision`), and a domain's shape leaking into a shared file is caught by a guard test — the "one module per slice" rule is CI-enforced, not a convention to remember. (ADR-0022.)
- **Health tiers** — how the bundled catalog is organised, by what an apply can break and how often it's worth checking: the **quick tier** (Suite **CI Gate**: Workspace access, Unity Catalog data path — read-only, about a minute, after every apply), the **compute tier** (Suite **Post-apply health: compute & network**: classic and serverless job probes, SQL warehouse cold start, a UC write round-trip — R1, `full` depth, minutes) and **security posture** (Suite **Security posture (drift)** — configuration drift read as an admin; **never** in the CI Gate). Every bundled Test is a **Test script** whose checks **assert** on what they read; a check that only proves "the API answered" doesn't belong in the catalog.
- **Canary fixtures** — the known objects provisioned in **every** workspace so the health tiers can prove the data path end to end: a catalog + schema, a one-row table (`ping`), a table **never granted** to the test identity (`forbidden`, the counterfactual's object), an **external volume** on the workspace's real external location holding one file, and a **scratch** schema for writes. Created by the `infra/canary` Terraform module (alongside the workspace's own configuration, with non-authoritative grants) or `provision_canary.py`; their names reach the Tests as **Target tags** (`canary_catalog`, `warehouse_id`, `expected_metastore_id`, …) read with `setting()`. Not the same as a Target's safety class — fixtures say *where*, safety class says *how dangerous*.
- **Target setting** — a per-Target value a Test script reads with `setting(key, default)`: a **run param** wins, then the Target's **tag** of the same name, then the default. This is what keeps one script target-agnostic. A check whose Target lacks a setting it needs calls `skip(reason)` and is recorded **`SKIPPED`** with that reason, never a vacuous pass.
- **Retired Test** — a bundled Test a newer release superseded. Seeding a database an older release seeded **upgrades** it instead of skipping: superseded seeded Tests are retired **in place** (disabled, renamed `… (retired)`, tagged `retired`, removed from every Suite, hidden from the Tests list) — never deleted, because Run history points at them — and the new catalog's Tests and Suites are added; the CI Gate's membership is reset to exactly the current gate. A human-authored Test is never retired.
- **Demo mode** — running with no workspace connection: scripts run against a stateful stand-in workspace that has the canary fixtures, so Checks give realistic results without a real one. Against a real workspace the stand-in is never used — a verdict comes only from what the workspace returned.
- **Release notes** — the user-facing record of what changed in each shipped version, **newest first**. Lives **in the repo** as `RELEASE_NOTES.md` (one `## vX.Y.Z — date` block per release: a short summary, then `###` sections of one-or-two-sentence bullets written for someone *using* the app, not reading the diff) and is rendered **read-only** under **Settings → Release notes** with a per-version nav. It describes the code, so it ships with the code — **not** a Lakebase record, not runtime-editable, not audited (contrast **Branding settings**). The newest release **must equal `APP_VERSION`** — a version bump without a note (or a note for an unshipped version) fails CI.

## Retired terms

These terms named parts of the structured Tests that Python scripts replaced. They were removed in v1.1.0, along with their run history; they survive only in the ADRs that recorded them. Don't use them for anything current.

- **Handler** / **handler manifest** / **`handler_key`** — the plugin that performed a structured Check's single operation, and its self-description of stages, risk tiers and parameters. Replaced by the script's own brokered calls (`w`, `w.api`, `sql()`, `http()`); a script Check reports `handler_key` `script`.
- **Structured Check** — a Check stored as one operation (`service`, `method`, `params`) plus an expected outcome and a plain-text assertion. Replaced by a `with check("…"):` block.
- **Evaluator** (`deterministic` / `agentic`) — how a structured Check's assertion was judged; `agentic` meant a pinned LLM judge whose verdict was always advisory. Every Check is now judged by its script's own `assert`s; advisory is `advisory=True`.
- **`deterministic-only` Suite** — a flag that kept `agentic` Checks out of a Suite's verdict. Nothing is agentic now, so it has no effect.
- **Worked-example library** — the gold structured Tests the Assistant grounded on and users could **promote** accepted Tests into. The Assistant now grounds on the SDK and docs; the shelf's starter prompts are a fixed list.
- **Derivation panel** — the Tests-page panel explaining how the Assistant derived a structured Check (handler, operation, parameter provenance).
- **YAML export** — the read-only YAML view of a Test or Suite. A Test's source is its script.
- **Converted test** — a structured Test shown in the editor as a generated script and converted when saved ("Edit as script", "Save as script").
- **`demo_*` params** — per-Check parameters that faked a structured Check's result in demo mode. Demo mode now runs scripts against a stand-in workspace.
