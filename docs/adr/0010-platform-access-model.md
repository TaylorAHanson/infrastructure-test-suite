# Platform access model: host identity, no app-local roles, friction-ceremony guards

The platform can register targets, set the safety class the safety gate trusts (ADR-0004), author Tests, trigger runs, and exercise the safety override — so we had to decide who, among human users, may do each, and whether to build an app-local role/RBAC system. Under the effort's OSS litmus (a stranger understands it with no docs) and "invent as little as possible" bias, we ship **no app-local authorization model**: authentication is the host Databricks App identity (every user is a workspace user; no app-local accounts), and every authenticated **human** app user has **full capability** — register/edit targets, set or downgrade safety class, author/edit Tests, trigger runs, and exercise the safety override. There are no roles, no admin group, and no per-object ACLs.

The dangerous, safety-gate-defeating actions are **not** gated by permission; they are guarded by a **friction ceremony** — a GUI-only gauntlet of escalating warnings that state, in concrete terms, what is about to be allowed and why it is dangerous, ending in an AWS-style typed confirmation (e.g. type "i understand"). This guards the **safety-class change** (especially the `prod-for-us`→`sandbox` downgrade) and the **safety override** (which already carried a typed confirmation, ADR-0004). Every such action is **audited**; with no preventive gate, the audit trail is the standing control. This governs **human** users only — machine identities are unchanged and stay least-privilege: the CI trigger identity is scoped to trigger + read, never override, never safety-class change (ADR-0005), and per-target SPs are least-privilege (ADR-0003).

## Consequences

- **Accepted risk:** any human app user can downgrade a real-production target and then run a destructive (R2) operation against it. The friction ceremony makes the downgrade deliberate and the audit log makes it attributable, but nothing *prevents* it. This is a trust-the-team, log-everything posture chosen for OSS learnability over preventive RBAC.
- **The absolute wall survives regardless:** **R3 is globally forbidden** through all three enforcement layers (ADR-0004), independent of safety class — no ceremony and no user can reach it.
- **Layer preventive control in the host, not the app:** a deployment that needs preventive limits controls *who is granted access to the App at all* via the host workspace — the platform does not reinvent that.
- **The audit-log model is now load-bearing** (previously implicit). What it records, where it lives, and how it is surfaced is left as open fog on the map, not decided here.
